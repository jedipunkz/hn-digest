APA の測定によると、コンテキストの切り替えからの回復には平均 23 分かかります。 ADHD 開発者にとっては、さらに長くなります。あなたの脳は無意識のうちにコンテキストを切り替え、Slack メッセージ、ランダムな思考、電子メール通知を受け取り、構築していたものに戻るには、メンタル モデル全体を再構築する必要があります。すべてのリビルドには 23 分以上のデッドタイムが発生します。
「この 1 点だけを修正してみます」は 4 時間のうさぎの穴になります。時間盲目はADHDの特徴です。時間の経過を感じることができません。タスクにどれくらいの時間がかかるかを見積もることはできません。締め切りに追われてパニック状態でコードを出荷してしまうのは、あなたが怠け者だからではなく、外部マーカーがないと脳が継続時間を認識できないからです。
ドキュメントを書くには、新規性の低いタスクに継続的に注意を払う必要があります。 ADHD の脳は、目新しさを集中力を維持する燃料として扱います。繰り返しの説明、文脈の再定義、決定の再説明、同じパターンの再文書化は、燃料を急速に消費します。文書化したくないわけではありません。それは、そのタスクがあなたの実行機能を維持できないということです。

クロード・コードはどのようにしてADHDの摩擦を軽減するのでしょうか?
Claude Code は 3 つのメカニズムを通じて ADHD の摩擦に対処します。1 つはセッション間でプロジェクトの状態を保存するため、再度説明する必要がないようにするコンテキスト キャッシュ、クロードが自動的に読み取る永続的な外部ファイルにドキュメントをオフロードする CLAUDE.md テンプレート、そして漠然とした目標をアトミックなタスク リストに分解し、白紙の状態での麻痺を定義されたリストからの単純な選択に置き換えるマルチエージェント オーケストレーションです。
なぜClなのか

Aude コードは ADHD の脳に機能します
Claude Code には、ADHD の摩擦点に直接対処する 3 つの機能があります。
クロードとの会話はすべて終了します。文脈が消えてしまいます。明日は、すべてを一から説明し直します。 ADHD 開発者にとって、これは壊滅的なことです。自分の仕事を担っていた外部構造を失っただけなのです。
コンテキスト キャッシュは、ユーザーが再度説明しなくても、クロードがセッション全体でプロジェクトの状態を記憶していることを意味します。ラップトップを閉じます。戻ってきてね。クロードはコンテキストをキャッシュしました。再説明はありません。メンタルモデルを再構築する必要はありません。中断したところから再開します。
特徴2: CLAUDE.mdテンプレート
ドキュメントを自分で管理する代わりに、テンプレートにオフロードします。 CLAUDE.md は、 ~/.claude/CLAUDE.md にあるプロジェクト内の単一の Markdown ファイルです。以下をキャプチャします。
プロジェクトのコンテキスト (何を構築しているのか?)
ルール (どのような制約があなたの脳を助けますか?)
既知の学習 (何を発見したか?)
非同期チェックポイント (中断された場合、どこから再開できますか?)
クロードはこれを自動的に読み上げます。改めて説明する必要はありません。テンプレートが説明を行います。完全な Claude Code ガイドでは、ADHD ワークフローだけでなく、あらゆる機能をカバーしています。
機能 3: マルチエージェント オーケストレーション
あなたがタスクをステップに分解する代わりに、クロードがそれを行います。あなたは目標を説明します。クロードはそれをアトミックなタスクに分割します。タスクを 1 つ選択し、そこから開始します。
これでイニシエーション麻痺が解決します。壁は「何をするか」ではありません。もう。それは「これを一つやってみよう」ということです。リストから 1 つを選択することは、白紙の状態から何をするかを決定するよりもはるかに簡単です。

ステップ 2: ADHD に優しいルールを定義する
プロジェクトのルールではなく、頭脳のルールです。これらは、あなたの特定の脳機能を助ける制約です。
## ADHD 開発者のためのルール
1. **質問は 1 つだけのルール**
- 1 つのメッセージでクロードに複数の質問をしないでください
- 質問が 3 つある場合は、3 つのメッセージを送信してください
- コンテキスト切り替えのコストは実際に発生します
2. **証拠優先の完了**
- 「動作するはずだ」という主張を受け入れないでください
- 実際のビルド出力、テスト結果、スクリーンショットが必要
- 証拠が明確であれば、決断力の麻痺は消える
3. **非同期チェックポイント更新**
- 45 分ごとに一時停止し、現在の状態で CLAUDE.md を更新します
- 何が機能したのか、何がブロックされたのか、次に何が起こるのかを文書化します
- 中断された場合でも、コンテキストを再構築せずに再開できます
4. **タスクの原子性**
- 休憩

45分以内に完了できるタスクに取り組む
- ADHDの脳は目新しさに過度に集中し、それを利用することができます
- 1 つの完了したタスクは 3 つの中途半端なタスクよりも優れています
5. **再説明は禁止**
- CLAUDE.md にある場合は、再度説明しないでください。
- 代わりにクロードにセクションを教えてください
- これによりコンテキストが保存され、認知的負荷が軽減されます。これらは普遍的なルールではありません。それらはあなたの脳のルールです。カスタマイズしてください。

ADHD creates four specific friction points that standard coding environments ignore: task initiation paralysis triggered by a blank editor, context switching that costs 23-plus minutes of rebuild time per interruption, time perception distortion that collapses deadline estimation, and documentation fatigue from sustained attention on low-novelty repetitive tasks.
The Problem: Your Brain vs. Your IDE
I’ve shipped code for five years. I understand programming deeply. But my ADHD brain creates four specific friction points that Claude Code solves:
The blank screen is paralyzing. Not because I don’t know what to do, I do. It’s that executive function barrier between knowing and starting. Research from the NIH shows ADHD involves significant deficits in task initiation and planning, as the CDC on ADHD also documents. Your brain literally can’t transition from planning mode to action mode without external structure.
The APA has measured this: recovering from a context switch takes an average of 23 minutes. For ADHD developers, it’s longer. Your brain involuntarily context-switches, a Slack message, a random thought, an email notification, and pulling back to what you were building requires rebuilding the entire mental model. Every rebuild is 23+ minutes of dead time.
“I’ll just fix this one thing” becomes a 4-hour rabbit hole. Time blindness is an ADHD hallmark. You can’t feel time passing. You can’t estimate how long tasks take. You ship code on deadline-driven panic, not because you’re lazy, but because your brain can’t perceive duration without external markers.
Writing documentation requires sustained attention on low-novelty tasks. Your ADHD brain treats novelty as the fuel that sustains focus. Repetitive explanation, redefining context, re-explaining decisions, re-documenting the same patterns, burns that fuel fast. It’s not that you don’t want to document. It’s that the task doesn’t sustain your executive function.
Claude Code doesn’t fix ADHD. But it offloads all four of these problems.

Step 1: Start with CLAUDE.md, Not Code
Before you write a single line of code, create a CLAUDE.md file in your project root:
# Project: [Your Project Name]
## Context
- What are we building?
- Who are we building it for?
- What's the current state?
## Rules (ADHD-Friendly)
- No multi-step questions in one message
- Always show evidence before claiming completion
- Async checkpoints every 30 minutes of work
## Known Learnings
- [ Issue ] → [ Fix ] → [Why it matters]
- [ Pattern ] → [When it works] → [When it fails]
## Current Checkpoint
- Last task: [what we were doing]
- Next task: [what we're doing now]
- Blocked by: [anything that needs resolution?] This file is your external executive function. It travels with you across sessions. Claude reads it automatically. You never re-explain again.
Step 2: Define ADHD-Friendly Rules
Not project rules, brain rules. These are the constraints that help YOUR specific brain function:
## Rules for ADHD Developers
1. **One Question Rule**
- Never ask Claude multiple questions in one message
- If you have three questions, send three messages
- Context-switching costs are real
2. **Evidence-First Completion**
- Don't accept "should work" claims
- Require actual build output, test results, screenshots
- Decision paralysis dies when evidence is clear
3. **Async Checkpoint Updates**
- Every 45 minutes, pause and update CLAUDE.md with current state
- Document what worked, what blocked, what's next
- If you get interrupted, you can resume without rebuilding context
4. **Task Atomicity**
- Break work into tasks completable in 45 minutes or less
- ADHD brains can hyperfocus on novelty, use it
- One complete task beats three half-finished ones
5. **No Re-Explaining**
- If it's in CLAUDE.md, don't explain it again
- Point Claude to the section instead
- This saves context and reduces cognitive load These aren’t universal rules. They’re rules for YOUR brain. Customize them.
