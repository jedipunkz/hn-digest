AI コーディング アシスタントで /graphify と入力すると、プロジェクト全体 (コード、ドキュメント、PDF、画像、ビデオ) がナレッジ グラフにマップされ、ファイルを grep する代わりにクエリできるようになります。
コードマップは無料で、完全にローカルです。コードはツリーシッター AST で解析されます。決定的、LLM なし、マシンから何も出ません。 (ドキュメント、PDF

、画像、およびビデオは、セマンティック パスのためにアシスタントのモデルまたは構成された API キーを使用します。)
あらゆるエッジが説明されています。各接続には EXTRACTED (ソースで明示的) または INFERRED (graphify によって解決) のタグが付けられるため、何が読み取られたのか、何が推論されたのかを直接区別できます。
ベクトルインデックスではありません。埋め込みやベクトル ストアはありません。実際のグラフをトラバースします。質問したり、2 つの物事の間の道をたどったり、1 つの概念を説明したりできます。
これを常時オンにして、オンデマンドだけでなく、コード、ドキュメント、会議全体でバックグラウンドで更新したいと思いませんか?それが私たちがgraphify.comで構築しているものであり、現在app.graphify.comで早期アクセスが公開されています。

PowerShell の注意: grify を使用してください。 /graphify ではありません。 — 先頭のスラッシュは、PowerShell のパス区切り文字です。
グラフ化: コマンドが見つかりません? uv tools install / pipx install は、graphify コマンドをツールの bin ディレクトリ ( ~/.local/bin ) に置きます。インストール直後にシェルがディレクトリを見つけられない場合 (新しい macOS + zsh セットアップではよくあることですが)、そのディレクトリがまだ PATH 上にありません。 uv ツール update-shell (または pipx ensurepath ) を実行して、新しいターミナルを開きます。プレーン pip を使用する場合は、 ~/.local/bin (Linux) または ~/Library/Python/3.x/bin (Mac) を PATH に追加するか、 python -mgraphify を実行します。
uvx / uv ツールをインストールする代わりに実行して実行しますか?コマンドではなくパッケージに名前を付けます: uvx --fromgraphifyy grify install 。プレーン uvx grify … 失敗します (解決策が見つかりません … grify のバージョンがありません)。これは、uv ツールの実行が最初の単語を package として読み取り、そのパッケージが grifyy であるためです。つまり、graphify コマンドがパッケージ内に存在します。
可能であれば、Mac/Windows への pip インストールは避けてください。このスキルは、実行時に Python をgraphify-out/.graphify_pythonから解決します。それが pip がパッケージをインストールした場所とは異なる環境を指している場合

げ、 ModuleNotFoundError: No module names 'graphify' が表示されます。 uv ツールのインストールと pipx のインストールは、独自の環境でパッケージを分離し、これを完全に回避します。
Git フックと uv ツール / pipx:graphify フック インストールは、インストール時に現在のインタープリター パスをフック スクリプトに直接埋め込むため、~/.local/bin が PATH にない GUI git クライアントや CI ランナーでも、コミット後のフックが正しく起動されます。 graphify を再インストールまたはアップグレードする場合は、graphify フック インストールを再実行して、埋め込みパスを更新します。
厳密モード (クロード コード):graphify install --project --strict により、アシスタントが実際にグラフを使用します。デフォルトのインストールでは、ファイルを読み取る前にgraphifyクエリを実行するように調整されます。 strict モードは、セッションの最初の生ソースの読み取りをブロックし、それをグラフにリダイレクトし、その後ナッジに戻ります (そのため、セッションごとに最大 1 回起動され、スタックすることはありません)。実行時に GRAPHIFY_HOOK_STRICT=1 / 0 で切り替えます。デフォルトのインストールは変更されません (ソフトナッジ)。
Codex ユーザーは、並列抽出のために ~/.codex/config.toml の [features] の下に multi_agent = true も必要です。 CodeBuddy は、Claude Code と同じエージェント ツールと PreToolUse フック メカニズムを使用します。 Factory Droid は、並列サブエージェントのディスパッチにタスク ツールを使用します。 OpenClaw と Aider は順次抽出を使用します (これらのプラットフォームでは、並列エージェントのサポートはまだ初期段階にあります)。 Trae は並列サブエージェント ディスパッチにエージェント ツールを使用し、PreToolUse フックをサポートしていないため、AGENTS.md が常時オンのメカニズムです。
--platform エージェント (エイリアス --platform skill ) は、一般的なクロスフレームワークのエージェント スキルの場所をターゲットにします。グローバル インストールの場合は仕様のユーザーグローバル ~/.agents/skills/ (npx スキルおよび仕様準拠のフレームワークによって読み取られます)、プロジェクト ( --project ) インストールの場合は ./.agents/skills/ です。ベアのgraphifyインストールは単一プラットフォーム(Claude Code)のままです。

設計 - .agents/skills を読み取るフレームワークでスキルを検出できるようにする場合は、名前付きエージェント プラットフォームを使用します。
Codex は /graphify の代わりに $graphify を使用します。
アシスタントが常にグラフを使用できるようにする
グラフを構築した後、プロジェクト内でこれを 1 回実行します。
これにより、コードベースの質問についてナレッジ グラフを参照するようにアシスタントに指示する小さな構成ファイルが書き込まれ、完全なレポートの読み取りや生のファイルの grep よりも、graphify クエリ "<question>" のような範囲指定されたクエリを優先します。
フック プラットフォーム (Claude Code、Gemini CLI): フックは、検索スタイルのツールを呼び出す前 (および、Claude Code では、Read/Glob ツールを介してソース ファイルを 1 つずつ読み取る前) に自動的に起動され、アシスタントをグラフ パスに誘導します。
命令ファイル プラットフォーム (Codex、OpenCode、Cursor など): 永続的な命令ファイル ( AGENTS.md 、 .cursor/rules/ など) は、同じクエリファースト ガイダンスを提供します。
GRAPH_REPORT.md は、広範なアーキテクチャのレビューのために引き続き利用できます。
CodeBuddy は、Claude Code と同じ 2 つのことを行います。つまり、アーキテクチャの質問に答える前に、CodeBuddy にgraphify-out/GRAPH_REPORT.md を読み取るよう指示する CODEBUDDY.md セクションを作成し、Bash の検索コマンドとファイルの読み取りの前に起動して、代わりにgraphify クエリに誘導する PreToolUse フック ( .codebuddy/settings.json ) をインストールします。
Codex は AGENTS.md に書き込みます。これは、このプラットフォーム上で常時オンのグラフ ガイダンスを実際に伝達するものです。また、graphify codex install は PreToolUse フックを .codex/hooks.json に登録します (graphifyhook-check) が、そのエントリは意図的に no-op です: Codex Desktop がフックSpe を拒否します

Type /graphify in your AI coding assistant and it maps your entire project (code, docs, PDFs, images, videos) into a knowledge graph you can query instead of grepping through files.
Code maps for free, fully local. Code is parsed with tree-sitter AST: deterministic, no LLM, nothing leaves your machine. (Docs, PDFs, images and video use your assistant's model, or a configured API key, for a semantic pass.)
Every edge is explained. Each connection is tagged EXTRACTED (explicit in the source) or INFERRED (resolved by graphify), so you can tell what was read directly from what was inferred.
Not a vector index. No embeddings, no vector store: a real graph you traverse. Ask a question, trace the path between two things, or explain one concept.
Want this always-on, updating in the background across your code, docs, and meetings rather than only on demand? That is what we are building at graphify.com , and early access is open now at app.graphify.com .

Install
Official package: The PyPI package is graphifyy (double-y). Other graphify* packages on PyPI are not affiliated. The CLI command is still graphify .
# Recommended (isolated env; if 'graphify' isn't found after, run: uv tool update-shell):
uv tool install graphifyy
# Alternatives:
pipx install graphifyy
pip install graphifyy # may need PATH setup — see note below
Step 2 — register the skill with your AI assistant:
graphify install
That's it. Open your AI assistant and type /graphify .
To install the assistant skill into the current repository instead of your user
profile, add --project :
graphify install --project
graphify install --project --platform codex
Project-scoped installs write under the current directory, for example
.claude/skills/graphify/SKILL.md or .agents/skills/graphify/SKILL.md (plus a
references/ sidecar the skill loads on demand), and
print a git add hint for files that can be committed.
Per-platform commands that support project-scoped installs accept the same flag,
for example graphify claude install --project or graphify codex install --project .
PowerShell note: Use graphify . not /graphify . — the leading slash is a path separator in PowerShell.
graphify: command not found ? uv tool install / pipx install put the graphify command in their tool bin dir ( ~/.local/bin ). If your shell can't find it right after install — common on a fresh macOS + zsh setup — that dir isn't on your PATH yet: run uv tool update-shell (or pipx ensurepath ), then open a new terminal. With plain pip , add ~/.local/bin (Linux) or ~/Library/Python/3.x/bin (Mac) to your PATH, or run python -m graphify .
Running with uvx / uv tool run instead of installing? Name the package, not the command: uvx --from graphifyy graphify install . Plain uvx graphify … fails ( No solution found … no versions of graphify ) because uv tool run reads the first word as a package , and the package is graphifyy — the graphify command lives inside it.
Avoid pip install on Mac/Windows if possible. The skill resolves Python at runtime from graphify-out/.graphify_python ; if that points to a different environment than where pip installed the package, you'll get ModuleNotFoundError: No module named 'graphify' . uv tool install and pipx install isolate the package in their own env and avoid this entirely.
Git hooks and uv tool / pipx: graphify hook install embeds the current interpreter path directly into the hook scripts at install time, so the post-commit hook fires correctly even in GUI git clients and CI runners where ~/.local/bin is not on PATH. If you reinstall or upgrade graphify, re-run graphify hook install to refresh the embedded path.
Strict mode (Claude Code): graphify install --project --strict makes the assistant actually use the graph. The default install nudges it to run graphify query before reading files; strict mode blocks the first raw source read of a session and redirects it to the graph, then reverts to the nudge (so it fires at most once per session and never gets stuck). Toggle at runtime with GRAPHIFY_HOOK_STRICT=1 / 0 ; the default install is unchanged (soft nudge).
Codex users also need multi_agent = true under [features] in ~/.codex/config.toml for parallel extraction. CodeBuddy uses the same Agent tool and PreToolUse hook mechanism as Claude Code. Factory Droid uses the Task tool for parallel subagent dispatch. OpenClaw and Aider use sequential extraction (parallel agent support is still early on those platforms). Trae uses the Agent tool for parallel subagent dispatch and does not support PreToolUse hooks, so AGENTS.md is the always-on mechanism.
--platform agents (alias --platform skills ) targets the generic cross-framework Agent-Skills locations: the spec's user-global ~/.agents/skills/ (read by npx skills and spec-compliant frameworks) for a global install, and ./.agents/skills/ for a project ( --project ) install. The bare graphify install stays single-platform (Claude Code) by design — use the named agents platform when you want the skill discoverable by any framework that reads .agents/skills .
