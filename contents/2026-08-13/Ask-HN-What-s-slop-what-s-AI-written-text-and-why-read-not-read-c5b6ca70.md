HN テキスト: 質問です。HN をよくチェックしているのですが、「明らかに AI が書いたものだから読まなかった」という傾向に気づいた、または処理できなかった、または散文的な書き方が嫌いでした。また、AI が生成したコードに対する同様の動作は、AI が提出したパッチ/PR に関する複数の AI ポリシーにも反映されています。ここで質問します。x の製品、または y の改善 (OSS へのパッチとして、または AI が役立つものなら何でも) についてアイデアがあるとします。その場合、a) このチームにアウトソーシングします。ローカルで同じ言語を使用します。それに取り組んでいる人に挨拶に行って、出力を確認せずに github に投稿します。
b) チームはあなたの国にあり、挨拶に行くのはさらに困難ですが、出力をレビューせずに github に投稿します
c) 同じだがチームは別の国にある
d) 同じですが、作業は請負業者の請負業者によって行われます。これもレビューせずに github に投稿します。
e) 無料の chatgpt バージョンに質問し、レビューせずに github に投稿します
f) 20 ドルのクロード アカウントで俳句を依頼し、レビューせずに github に投稿してください
g) クロード神話を依頼してください... ものをハッキングするバージョンは、空隙のある磁場に含まれなければなりません... 出力をレビューせずに github に投稿してください... どこからがずさんで、どこからがそうでないのでしょうか?
今、その代わりに、出力をレビューし、読んで理解し、それが機能することを確認するために自分自身にドッグフィードし、3 週間テストし、100 ラウンドの研磨を経て、github に投稿したとしたら... それは同じでしょうか、違うでしょうか?そうでない場合、AI は問題ではありません...問題は、レビューされていない、ガイドされていない、テストされていない、「耐荷重の決定」が 5 回あったとしてもチェックしなかった、急いで行われたことです。 AI スタイルのライティングが問題である場合、AI かどうかに関係なく、磨きをかけることが重要です。

それが問題です。 AI 擁護の議論ではありません。もし今夜この問題が消えたとしても、神に感謝します。私たちは再び RAM と GPU を良識的な価格で購入できるようになり、私たちが使用しているソフトウェアに対して、素早く、急いで、PR を行うかどうかにかかわらず、狂気の波を止めることができるでしょう。
