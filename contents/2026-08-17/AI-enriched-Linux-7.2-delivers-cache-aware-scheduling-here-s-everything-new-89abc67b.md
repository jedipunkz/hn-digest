最新の Linux カーネルには、多くの AI 修正が組み込まれています。
キャッシュを意識したスケジューリングにより、処理が高速化されます。
最新のカーネルには他にも改良が加えられています。
Linus Torvalds 氏は、週末に Linux カーネル 7.2 のリリースを発表しました。彼は、「先週のリリースは、またしても、私が望んでいたよりも大規模なものでした。しかし、まあ、『ニューノーマル』ということもあり、もし私がその理由でリリースを遅らせていたら、おそらくリリースはまったく行われなかっただろう。」と書いている。
「ニューノーマル」だと思いますか？彼はこれについて、Linux 7.2 の 7 番目のリリース候補に関するメモの中で以前に説明しました。 「この規模の大きさにまったく興奮しているとは言えません。しかし、それが現実です。多くの修正が加えられた新常態であり、その多くはさまざまな AI ツールによるレビューによるものです。」
これらの変更は、大部分が AI によって作成された新機能ではなく、AI によって発見されたセキュリティ脆弱性に対するパッチであり、積み重なっていきます。
関連記事: 「私はもうプログラマーではない」: リーナス・トーバルズ氏が現在使用している唯一のツールについて語る
Linux カーネル 7.1 のリリース前に Torvalds 氏は次のように述べていました。「AI レポートの洪水が続いているため、基本的にセキュリティ リストはほぼ完全に管理不能になっており、異なる人が同じツールを使って同じものを見つけているため、膨大な重複が発生しています。人々は、適切な人に物事を転送するか、『それは 1 週間または 1 か月前にすでに修正されています』と言うだけですべての時間を費やしています。」
「これはまったく無意味な混乱であり、AI が検出したバグは定義上機密ではないこと、そしてそれらを非公開リストで扱うことは関係者全員にとって時間の無駄であり、重複を生むだけであることを明らかにしています。

さらに悪いことに、記者たちはお互いのレポートを見ることさえできないのです。」
だからといって、トーバルズ氏がAIの利用に反対しているわけではない。 Torvalds 氏は、「 AI ツールは素晴らしいですが、それは不必要な苦痛や無意味なごまかしを引き起こすのではなく、実際に役立つ場合に限ります。」自由に使用してください。ただし、生産的でより良いエクスペリエンスをもたらす方法で使用してください。」
Linux の最前線に住んでいない限り、Ubuntu 26.10 などの秋の Linux ディストリビューションがリリースされるまで、これらの機能を目にすることはほとんどありません。それでも、ほとんどのアップデートは、複雑な CPU キャッシュ レイアウト、新しいグラフィックスとモバイル ハードウェア、およびストレージ集中型のワークロードを備えたコンピュータで最大限の利点を発揮します。
注目の追加機能は、数年前から開発されている新しいキャッシュ スケジューリング プログラムである Cache Aware Scheduling です。 Torvalds 氏は再び次のように述べています。「一連のパッチの目標は、データを共有するタスクを同じ LLC キャッシュ ドメインに集約し、それによってキャッシュ バウンスやキャッシュ ミスを減らし、データ アクセス効率を向上させることです。」
関連記事: Linux を 30 年間使用してきた私が、Windows ユーザーに Linux への移行を説得する方法を紹介します。
以前は、スケジューラは、別個のコア上のスレッドがメモリを共有しているかどうかをチェックせずに、CPU のコア全体で負荷のバランスをとっていました。これは、異なるコア上のスレッドが同じデータを再フェッチすることを意味しました。これにより、システムが同じデータを取得したり再取得したりすることで時間とリソースが無駄になるキャッシュバウンスが発生しました。現在、プロセスはよりクリーンで無駄が少なくなりました。
このコードには、キャッシュ ドメインの過負荷を回避するためのガードレールが含まれています。また、プロセスがすでに CPU 時間の 25% 以上、またはドメイン負荷の 3 分の 1 以上を消費している場合に、それ以上のスレッドの移動を回避します。マルチスレッド サーバー、AI および ML コンピューティング ジョブ、一部のゲームなどのワークロードは、この改善から最も恩恵を受けるでしょう。
いつものように、そこには

新しく改良されたドライバー。その中で最も重要なものは、HDMI 2.1 固定レート リンク (FRL) の初期 AMDGPU サポートです。この新しい HDMI テクノロジーにより、非圧縮 4K (120Hz) および 8K ビデオを表示できます。また、AMD プロセッサと Intel プロセッサの両方で I/O 速度の向上が見られます。
I/O に関して言えば、Btrfs のラージ フォリオがついに実験段階から脱却し、デフォルトで有効になりました。実際には、これはシーケンシャル書き込みが 15% 向上することを意味します。
同時に、最大 2 MB の実験的な Folio も導入されました。このリリースでは、ext4 および XFS の I/O マップ変換作業が継続されますが、exFAT には大きなファイルのパフォーマンスを向上させることを目的とした変更が加えられています。
また: OpenFactory を使用して独自の Linux ディストリビューションを一晩で構築しました - この AI ツールは大きなものになるでしょう
Linux 7.2 での Windows NTFS 処理も改善され、いくつかの小さなバグが修正されました。 SD カードや USB スティックで一般的に使用される形式である ExFAT は、カーネルの iomap を使用するようになりました。これにより、これらのデバイスの読み取りおよび書き込み速度が 87% も向上し、USB ドライブからの Linux ディストリビューションの実行が大幅に高速化されます。
新しいカーネルでは、インテルが開発した USB4STREAM プロトコルのサポートも追加され、USB4/Thunderbolt リンクを介した生のホスト間ストリーミングが可能になります。実際には、これは「基本的に生のパケットをあるホストから別のホストに転送するだけ」の「非常に簡単な」方法です。これは、従来の Linux ネットワーク スタックを回避しながら、あるホストから別のホストにシステムを迅速にバックアップしたり、システム間で Web カメラやその他の周辺機器を共有したりする場合に役立ちます。
ネットワークについて言及していますが、このリリースでは Wi-Fi Aware と初期の Wi-Fi 8/UHR グラウンドワークが追加されています。 Wi-Fi Aware を使用すると、従来のネットワーク インフラストラクチャを必要とせずに、デバイス間の Wi-Fi 接続が可能になります。これは、Apple AirDrop を強化したものと考えることができます。
ついに、そこにｗ

1 つの重要なロールバックとして。最近のテストでは、一部の AMD グラフィックス構成で「より公平な」GPU スケジューラ アプローチによるパフォーマンスの低下が明らかになりました。したがって、Linux 7.2 では、変更を出荷するのではなく、FIFO スケジューリングに戻ります。
全体として、新しい Linux カーネルはそれほど大きな見出しを集めることはないかもしれませんが、特にファイル システムとネットワークのパフォーマンスの向上においては、大きな前進です。

Linux 7.2 ソースは現在入手可能ですが、ほとんどのユーザーはディストリビューションのカーネル パッケージと検証プロセスを待つ必要があります。これは、サードパーティのカーネル モジュール、ドライバー、セキュア ブート ポリシー、ベンダー認定が遅れている運用システムでは特に賢明です。
独自のカーネルをコンパイルすることに慣れていないが、できるだけ早く使いたい場合は、Arch Linux が 7.2 のバージョンをリリースする可能性が最も高いメジャー ディストリビューションであり、その次に Fedora Rawhide 、openSUSE Tumbleweed 、Gentoo が続きます。

Linus Torvalds announced the release of Linux kernel 7.2 over the weekend. He wrote, "This last week of the release was -- once again -- bigger than I would have wished for, but hey, with the whole 'new normal' thing, if I delayed releases for that reason, we'd probably never have a release at all."
"New normal," you ask? He explained this earlier in his note about Linux 7.2's seventh release candidate. "I can't say that I'm exactly thrilled about the size of this all. But it is what it is: the new normal with a lot of fixes, many of them due to review by various AI tools. "
These changes -- which are largely not new features written by AI, but patches to AI-discovered security vulnerabilities --add up.
Also: 'I'm not a programmer' anymore: Linus Torvalds on the only two tools he uses now
Before the release of the 7.1 Linux kernel, Torvalds had said, "The continued flood of AI reports has basically made the security list almost entirely unmanageable , with enormous duplication due to different people finding the same things with the same tools. People spend all their time just forwarding things to the right people or saying 'that was already fixed a week/month ago.'"
"This is all entirely pointless churn, and we're making it clear that AI-detected bugs are pretty much by definition not secret, and treating them on some private list is a waste of time for everybody involved - and only makes that duplication worse because the reporters can't even see each other's reports."
That's not to say Torvalds is against using AI. Torvalds has noted that " AI tools are great , but only if they actually help, rather than cause unnecessary pain and pointless make-believe work. Feel free to use them, but use them in a way that is productive and makes for a better experience."
Unless you live on Linux's bleeding edge, you're unlikely to see these features until the release of fall Linux distros, such as Ubuntu 26.10 . Even then, most of the updates will show their best advantage on computers with complex CPU-cache layouts, newer graphics and mobile hardware, and storage-intensive workloads.
The marquee addition is Cache Aware Scheduling , a new cache scheduling program that's been in the works for several years. Torvalds again: "The goal of the patch series is to aggregate tasks sharing data to the same LLC cache domain, thereby reducing cache bouncing and cache misses, and improving data access efficiency."
Also: After 30 years with Linux, here's my way of convincing Windows users to switch
Previously, the scheduler balanced load across your CPU's cores without checking whether threads on separate cores shared memory. This meant threads on different cores would re-fetch the same data. This led to cache bouncing, where your system wasted time and resources pulling and re-pulling the same data. Now, the process is much cleaner and less wasteful.
The code includes guardrails to avoid overloading a cache domain. It also avoids further thread movement when a process already consumes more than 25% of CPU time or more than one-third of a domain's load. Workloads such as multithreaded servers, AI and ML compute jobs, and some games will benefit the most from this improvement.
As usual, there are new and improved drivers. Foremost among these is initial AMDGPU support for HDMI 2.1 Fixed Rate Link (FRL). This new HDMI technology enables you to view uncompressed 4K at 120Hz and 8K videos. You'll also see I/O speed improvements with both AMD and Intel processers.
On the subject of I/O, Btrfs large folios have finally left experimental status and become enabled by default. In practice, this means 15% improvements in sequential writes .
At the same time, experimental folios up to 2 MB have also been introduced. The release continues I/O-map conversion work for ext4 and XFS, while exFAT gains changes intended to improve large-file performance.

Windows NTFS handling in Linux 7.2 has also been improved, and some minor bugs have been fixed. ExFAT, the commonly used format on SD cards and USB sticks, is now using the kernel's iomap . This will improve the read and write speed on these devices by as much as 87% , and make running a Linux distro from a USB drive much faster.
The new kernel also adds Intel-developed USB4STREAM protocol support, enabling raw host-to-host streaming over USB4/Thunderbolt links. In practice, this is a "super simple" way to "basically just transfer raw packets from one host to another." This can be useful for quickly backing up a system from one host to another, sharing web cameras or other peripherals across systems while avoiding the traditional Linux networking stack.
While we're mentioning networking, this release adds Wi-Fi Aware and early Wi-Fi 8/UHR groundwork. Wi-Fi Aware enables device-to-device Wi-Fi connections without the need for a traditional network infrastructure. You can think of this as Apple AirDrop on steroids.
Finally, there was one significant rollback. Late testing revealed a performance regression with a "fairer" GPU scheduler approach on some AMD graphics configurations. Linux 7.2 therefore reverts to FIFO scheduling rather than shipping the change.
All in all, the new Linux kernel may not garner many headlines, but it's a significant step forward, especially in file system and networking performance improvements.

The Linux 7.2 source is available now, but most users should wait for their distribution's kernel packages and validation process. That is especially sensible on production systems, where third-party kernel modules, drivers, secure-boot policies, and vendor certification lag behind.
If you aren't comfortable compiling your own kernel but still want to jump in as fast as possible, Arch Linux is the likeliest major distro to release a version with 7.2, with Fedora Rawhide , openSUSE Tumbleweed , and Gentoo close behind.
