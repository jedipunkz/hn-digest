HN text: これまでのソフトウェアのモデルは、通常、固定アプリケーションを出荷し、ユーザーがカスタム機能を必要とする場合は、プラグインをインストールするか、独自のプラグインを作成する必要がありました。技術者以外のユーザーの場合は、既存のプラグインを探す必要があるか、あるいはプラグインが存在しないため立ち往生している可能性があります。しかし、私は、たとえばアプリケーションに、その場で動的に拡張機能を構築するプロンプト ボックスをなぜ持たないのか考えずにはいられません (例: 「X を実行するいくつかのボタンを備えた UI パネルを作成してください」)。明らかに、それは「自己責任で使用する」ことになり、YMMV になります。実際にこのようなことを行った企業やアプリケーションはありますか?実際のソース コードを変更するのは手に負えなくなると思いますが、おそらく、より安全な API のサンドボックス セットにアクセスできる拡張機能を生成するだけでよいでしょう。

## Original Extract

In the past the model for software would typically be to ship a fixed application and then if users need some custom functionality, they would need to install a plugin or create their own. For non technical users they would have to find an existing plugin or maybe it doesn't exist so they are stuck. But I can't help but think why wouldn't for example an application just have a prompt box that builds an extension dynamically on the fly (e.g. "make me a UI panel with some buttons that does X") Obviously it would be "use at your own risk" and YMMV Have any companies or applications actually done something like this? I think modifying the real source code would get out of hand but perhaps just generating extensions that have access to a sand boxed set of safer APIs.
