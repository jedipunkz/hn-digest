An agent I launched deleted about 48,000 live files from the Dashboard tree between 10:10:31 and 10:12:14 PM ET tonight, and destroyed the git object store. I've confirmed it myself, independently of the agent's own report.
What happened. Your item 3 authorized rebuilding the #873 mirror. build_mirror.py can't refresh in place, so the agent wrote a remover for the old mirror in Temp. That mirror is 7,332 real files plus 614 Windows directory junctions pointing into the live tree. Its remover used os.walk(..., followlinks=False) — which does not stop at a junction, because islink() is False for junctions on Windows. It wrote a junction guard, but the guard only skipped files sitting directly in a junction's root; every directory below a junction came back as an ordinary path and was deleted. Its own log: 55550 files, 614 junctions, 1808 dirs. Minus the 7,332 real mirror files, that's 48,218 live files.
Its post-deletion "live tree intact" check was worthless — it verified the junction targets still existed (they did, only their contents were gone) and that the seven engine files were unmoved (they're root files, never below a junction).

How to recover deleted files
To recover deleted files, first check your recycle bin or cloud service's trash, then use data recovery software, or consider professional recovery if the data is crucial and not overwritten.
Recycle Bin/Trash : Look in your computer's recycle bin or trash folder, as files often reside there for a period before permanent deletion. "Go to "file" you will see the recycle bin, it will be there. Restore what you want. The recycle bin keep it for 30 days before it permanently delete it."
Cloud Backups : If the files were synced with a cloud service like Dropbox, Google Photos, or OneDrive, check their respective deleted files or file history sections. "If the files were deleted from a synced folder, first check the Dropbox website → Deleted files and restore from there."
Stop Using the Device : Immediately cease all activity on the device where the files were deleted to prevent new data from overwriting the deleted files. "At this point I’d probably stop installing or running anything else on the phone."
Free Software : Tools like Recuva and TestDisk are often recommended for recovering files, though original names and folder structures may not always be preserved. "Recuva is commonly recommended."
Paid Software : If free options are insufficient, consider paid software like Disk Drill or EaseUS Recovery, which may offer more robust recovery algorithms. "If you want to play extremely safe, the first thing is I would make a clone of the external drive. Then work on the clone instead of the main drive."
Installation Location : Always install recovery software on a different drive than the one you are trying to recover files from to avoid overwriting the deleted data. "If you need to install recovery tools, don't install them on the same drive as the files you want to recover!"
Complex Cases : For highly important files or when DIY methods fail, professional data recovery services have specialized tools and expertise to retrieve data from severely damaged or overwritten drives. "If you’re looking for your best chances at recovering the files I would honestly look into professional recovery..."
Cost : Professional services can be expensive, but they offer the best chance for recovery, especially for data lost on modern devices with encryption. "I think they are gone due to encryption keys being deleted with the files. A quick search on Reddit or Google will explain why as its not the first time this has happened."
