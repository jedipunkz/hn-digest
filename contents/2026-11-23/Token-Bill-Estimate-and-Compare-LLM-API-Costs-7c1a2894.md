見積もりの計算方法
リクエストあたりのコスト = 入力トークン × 入力価格 ÷ 1,000,000 + 出力トークン × 出力価格 ÷ 1,000,000。
月額コスト = リクエストあたりのコスト × 1 日あたりのリクエスト数 × 30。年間 = 月額 × 12。
キャッシュ: 入力のキャッシュされた部分はキャッシュ読み取り価格で請求され、残りは通常の入力価格で請求されます。キャッシュ価格が公開されていないモデルは、入力価格全体で請求され、タグ付けされます。
バッチ: ボックスにチェックを入れると、バッチ API を備えたモデルはバッチ価格で請求されます。ほとんどのモデルは半額、一部のモデルは若干の割引になります。
長いコンテキスト: プロンプトがモデルのしきい値を超えると、プロバイダーが請求するため、より高い料金がリクエスト全体に適用されます。
プロモーション: プロモーション価格は終了日まで使用され、その後の価格がモデルの横に表示されます。

トークンとは、

モデルが読み書きするテキストの一部。英語では、1,000 トークンは約 750 単語に相当します。他のほとんどの言語では、同じテキストに対してより多くのトークンが必要であり、アラビア語では英語の約 2 倍のトークンが必要になることがよくあります。各プロバイダーには独自のトークナイザーがあるため、カウントは多少異なります。上記のテキスト推定ツールは、大まかな数字を示します。
応答の作成にはプロンプトの読み取りよりも多くのコンピューティングが必要となるため、プロバイダーは出力トークンごとに数倍の料金を請求します。長い回答や推論モデルでは料金がすぐに高くなるため、出力設定が見た目よりも重要になることがよくあります。
システム プロンプト、ポリシー、ドキュメントなど、多くのリクエストが同じテキストで始まる場合、プロバイダーはそれを保持し、後で読み取った料金を低料金で請求することができます。キャッシュされた共有を、入力の繰り返される部分に設定します。プロバイダーによっては、キャッシュの書き込みまたは保存に料金を請求する場合もあります。それらの料金はここには含まれていません。

How the estimate is calculated
Cost per request = input tokens × input price ÷ 1,000,000 + output tokens × output price ÷ 1,000,000.
Monthly cost = cost per request × requests per day × 30. Yearly = monthly × 12.
Caching: the cached share of input is billed at the cache-read price, the rest at the normal input price. Models with no published cache price are billed at the full input price and tagged.
Batch: when the box is ticked, models with a batch API are billed at their batch price: half price on most, a smaller discount on a few.
Long context: when the prompt goes over a model's threshold, its higher rate applies to the whole request, as those providers bill it.
Promotions: the promo price is used until its end date, which is shown next to the model with the price that follows.

A token is a piece of text the model reads or writes. In English, 1,000 tokens is about 750 words. Most other languages need more tokens for the same text, and Arabic often needs about twice as many as English. Each provider has its own tokenizer, so counts differ a little. The text estimator above gives a rough figure.
Writing a reply takes more computing than reading a prompt, so providers charge several times more per output token. Long answers and reasoning models raise the bill fast, so the output setting often matters more than it looks.
When many requests start with the same text, such as a system prompt, a policy or a document, the provider can keep it and bill later reads at a lower rate. Set the cached share to the part of your input that repeats. Some providers also charge to write or store the cache; those fees are not included here.
When nobody waits for the answer: tagging, overnight summaries, data extraction. Results arrive within up to 24 hours at about half price. It does not suit chatbots or anything interactive.
