Hush を使用すると、エージェントは作業を続けながら、バックグラウンドでコンピュータ上のアプリを確認して実行できるようになります。
ウィンドウを読み取り、クリックし、入力し、再度読み取ります: 178 ミリ秒。次に速いツールは 653 ミリ秒かかります。
これは、2200 の chess.com ボットに対して 1 分間の弾丸で勝利し、3 番目のゲームをプレイするのに十分な速さです。
月光ソナタをフルテンポですべての音符を時間どおりに動かし、10 人のエージェントを 10 人で実行します。
何も前面に表示されることなく、すべてのアプリを 1 台のマシン上で同時に実行できます。
同じウィンドウ、同じマシン、読み取り、クリック、入力、読み取りを 1 回繰り返します

Many agents at once
One Hush host serves every agent on your machine. It starts with the first command and goes away after
ten idle minutes. Each agent gets its own session with its own refs and diffs. Agents on different
apps run in parallel; two agents on the same app take turns, so their clicks and keys never
interleave.
Ten sessions hammering one host: 500 calls in 2.2 s, zero errors, observe in 48 ms and see in
28 ms at the median, on one core and 101 MB.
Agents don't need your screen. The lane step moves a window onto Hush's lane, a virtual display
nobody can see, parked off a corner of your main display where the pointer can't reach. Windows
there still render, take clicks and keys, and can be captured. Only that window moves, and it comes
back to where it was on unlane , the moment you switch to its app, or when the host exits.
On Linux the lane is a hidden X server that Hush starts for itself. Every app an agent opens runs
there from the start, whether your desktop is X11 or Wayland.
Decide what agents may touch, app by app, in ~/.config/hush/limits :
never 1Password, Keychain Access, Messages # agents can't see these
read Terminal, Mail # agents can read these, not act on them
only Notes, TextEdit, Terminal, Mail # with an only line, every other app is off limits
Names are app names or bundle ids. While any limits are set, script is off, since a script can
reach any app. hush apps marks limited apps, and a refused call tells the
agent the user chose it, so it reports back instead of trying something else. Every command and
new MCP session reads the file, so an edit applies at once. A file with a mistake stops Hush until
it's fixed, so nothing runs without the limits by accident.
record films a window while Hush works in it, lane included, and draws an agent cursor into the
video: it glides to each click, leans into its motion, dips with a ripple on clicks and carries a
name tag. The cursor lives only in the video, and the pacing is real.

Desktop tests
A test is a text file: the app, the steps, and expect lines that check the window. It names
elements the way the outline shows them, so it runs in any session, on any machine, with no model.
# notes.hush
app Notes
click button "New Note"
type textarea[1] "Groceries"
expect text "Groceries"
expect button "Delete"
hush test notes.hush # or a folder: hush test tests/desktop
Each file runs in a fresh session and stops at its first failure, saying what the window shows
instead ( expected = "Milk", but t2 field "Title" = "Mlk" ). A failed test leaves its outline and
a picture in hush-results/ , and with --record a movie of the run. Hush waits for each step to
settle instead of sleeping, so a test is as fast as the app and doesn't flake on timing. On Linux,
tests run on Hush's hidden display, which works on a CI runner with no screen.
An agent can write the test by doing the task once. Every step a session runs is kept with its
refs turned into what the outline showed, so hush save turns the run into a test that replays
with no model and no tokens:
hush act Notes ' click b1 ' ' type t2 "Groceries" '
hush save Notes notes.hush # app Notes · click button "New Note" · type textarea[1] "Groceries"
hush test notes.hush
